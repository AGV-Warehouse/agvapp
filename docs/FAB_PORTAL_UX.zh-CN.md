# Fab 搬运门户 UX 评审稿

状态：设计预览，不是生产实现。所有示例操作只在本地内存中更新；没有 API、部署或机器人控制。六入口是拟议信息架构，不是现有六条路由，也不建议复制六套应用。

页面目录与模块迁移边界见 [PAGE_DIRECTORY.zh-CN.md](PAGE_DIRECTORY.zh-CN.md)；现状证据见 [CURRENT_INTERACTION_AUDIT.zh-CN.md](CURRENT_INTERACTION_AUDIT.zh-CN.md)。

## 页面树与优先级

- P0 `/operations` 运行总览：2D RTS 地图中心，右侧所选车 / 站点；计划、授权、执行路线开关；owner、waitReason、age。此聚合视图待接入。
- P0 `/missions` 搬运任务：复用现有导航下单语义，选车、只读报告起点、目的站。表单必填与起终不同校验；本原型仅本地入队。请求受理、等待路权、行驶、到站分别表达。
- P0 `/maps` 地图与发布：背景、occupancy、openTCS graph 三层共同坐标与版本；已有草稿编辑能力，发布预检明确 M3 阻塞。
- P0 `/fleet` 车辆与连接：车辆身份、地图版本、连接会话、Worker 与就绪绑定门禁；正式 commissioning 待接入。
- P0 `/simulation` 虚拟实验：选图到记录的入口，分清独立 `/twin/` 四车演示与隔离 LAB 双车实验。
- P0 `/events` 事件与对账：断连、证据核对、关闭旧意图、另建新意图。完整历史检索及 UNKNOWN 对账 UI 待接入。
- P1 工位 / 载台 / 载具：总览抽屉。系统设置、权限、健康放次级入口，避免首屏膨胀。

## 首要闭环

默认入口改为地图页的“NPI 起步”。目标用户是只知道平面图与交互设备的新产品导入者；其任务是逐步形成可验证的模型与实验合同，不要求先理解 ROS 或 openTCS 内部实现。

NPI 主线及页面映射：资料建档 → 导入平面 / occupancy 或建立二维场景（地图）→ 放置资产、记录参数待确认（地图资产库）→ openTCS 点 / 路 / NOP 站 / Block（地图，复用现草稿编辑器）→ 校验冻结三层版本（地图）→ 虚拟 Worker / 车辆就绪（车辆与连接）→ 任务 / 负载 / 异常实验（虚拟实验与任务）→ 指标 / 回放报告（虚拟实验与事件）→ 现场校准与复验（后续交付阶段）。这是设计流程，并非新增实现。

原型新增三个本地准备入口：导入资料、建立二维场景、资产小库配置，另有完整准备清单。导入区分尺度 / 原点 / 朝向与已知、估计、待测；不实际上传服务器。二维场景入口说明当前 editor 只有点路站块、坐标、修订与导出，不假造几何 / 行为编辑器。

预加载布局选择器只登记候选并反馈“未加载地图，未改变运行示例 v0.2”，不伪装真实载入。资产弹窗可切类型查看说明，但参数表编辑尚未实现。

资产动作合同分别定义：停车位只导航 NOP；高桌载台为导航 → 停稳 → 估计桌位 / 确认在位及许可 → 精对准 / 受控钻入 → 顶升 → 独立承载确认 → 退出；机器站为导航停稳 → 设备 ready / 握手 → 交接反馈，不默认顶升；立牌终端为按钮意图 → 受理 / 排队 ACK → 车辆到站独立反馈，固定 Tag 仅作参考。后三者为未实现候选，不可执行。

资产库包含停车位、上下料 / 高桌载台位、机器交互站、ArUco 立牌终端；当前可执行资产仅导航 NOP Station，其他均“设计候选 / 未实现”。每类给出四层合同：几何与进入朝向 / capture 区；期望可观测 Tag、载台在位、按钮或设备握手；动作序列；成功与异常判据。进入 polygon 不直接成功，看到 Tag 不等于可以可靠顶升。StationID 绑定候选 TagID / ButtonID；固定 tagPose 与移动 tablePose、承载状态独立定义。

运行示例明确绑定 v0.2 已发布（仍是虚构示例），编辑草稿是 v0.3 待发布，避免草稿驱动进行中任务的语义混淆。地图 → 虚拟实验提供明确下一步入口；实验记录弹窗只登记计划 / 指标 / 回放需求，不生成测量数据或声称实际运行。

选预加载 / 假想布局 → 草稿校验 → 受控发布隔离 SIM → 虚拟车就绪并绑定地图版本 → 表单下导航任务 → 2D 计划 / 授权 / 执行和占用等待解释 → 取消 / 断连对账 → 留存记录。

MiniPC 承载 Fleetserver、openTCS、MQTT 与门户；ROS / Nav2 / Gazebo 虚拟机器人运行在本地或远程 Worker。当前没有通用 Worker 注册、任意场景创建或算法比较能力。

## 元素与交互合同

1. 顶部永久显示“设计预览 · 示例数据 · 不连接服务”和 SIMULATION。切到 REAL 时显示“未连接 / 只读”，所有本地任务写入与对账推进按钮禁用，不显示虚假 online。
2. 六入口原地切换内容；顶部新任务跳到表单。车辆与站点为原生按钮，地图对象选中更新侧栏。三种路线用文字、线型与色彩共同区分；复选框独立隐藏各路线。
3. 导航表单选择车辆，起点只读取报告点（此原型两车统一示例 ST-A），任务名及目的站必填；目的站不得等于起点。成功只新增 LOCAL 队列项，显示“请求受理（本地）”。不新增取货、Cart、Lot 或机台工序能力。
4. 请求取消只标记“取消待对账”，不能暗示急停或完成。进入事件页进行证据核对，关闭旧意图后跳到新任务表单，使用新 ID。

   本地对账关闭时，同步将关联 SIM-1042 队列状态标为“旧意图已关闭（本地示例）”，并禁用该条目的取消按钮；这不是后端真实终态。所选车辆详情将等待时长 waitDuration 与遥测新鲜度 sourceAge 分开展示，二者均为固定示例，不能相互替代。
5. 地图预检弹窗列三层坐标 / 字段示例通过项，及 M3 接口、目标 SIM 连接、Worker 就绪和车辆绑定阻塞；明确没有读取真实文件。弹窗支持关闭按钮、Escape 与背景点击。
6. 就绪门禁与实验准入按钮均给出明确检查结果，不是假按钮。Tweak 可切紧凑行距、工程详情；普通操作界面不暴露 ROS 节点或 C++。

## 事实与阶段标记

**已有：** index.html 单 shell 的 Overview / Vehicles / Transport orders / Activity；导航任务表单、FleetAPI create_order 的 robotId / destination 与幂等 requestId；未决意图约束、暂停与撤单。editor.html 有 Point / Path / Station / Block、YAML/PGM 导入、修订 / 校验 / bundle 与 openTCS JSON 导出。保存 / 导出只操作草稿。

**待接入：** M3 draft → live、目的站注册更新、地图分发、图车绑定 / commissioning、门户正式仿真运行。live model 投影没有完整 Block 成员、实时 owner 与三种路线聚合；R3c 报告字段不等于门户实时接口。完整事件检索与 UNKNOWN 对账 UI 也未完成。

**已验收但有限范围：** R3c 真双车互斥等待释放、移动取消、真实 MQTT 断连、同 PID 恢复后新 UUID 完成；范围为起点 0.12 m 容差、shared 外，不是通用 mid-edge 自动恢复，也不是 UI 已完成。`/twin/` 独立四车 Nav2 车道往返演示不等于 openTCS 调度验证。

**研究：** wafer 盒高桌式载台、从下钻入顶升、机器旁取放区、人车共行、实体低速 / safety lidar / 气悬。固定 ArUco 立牌优先评估，可绑定 StationID 并研究叫车按钮 / 灯；停车线和桌底 Tag 为候选。固定 Tag 只提供 station 参考，移动桌 pose 与承载确认必须独立。当前仅导航 NOP，无业务 dock / lift 节点动作。实测 PID、安全与减振应以包络、延迟、停止距离进入仿真模型。

## 实施与验收建议

优先复用现 shell 与 FleetAPI，不按拟议 URL 复制应用。下一实施项是只读连接版本化模型 / 车态 / 调度解释，然后才受控接入正式任务写入。三层地图的 frame、单位、原点、分辨率、yaw 和各修订必须整体核对；纸面布局不能当导航图。

评审原型路径：线程可视化目录的 `fab-fleet-portal.html`。已完成静态检查：JavaScript 语法、无网络请求 / 外部资源、HTML fragment 边界；root 静态审查后的候选布局反馈与资产类型动作合同已修订。实际浏览器点击与 320 px / 1024 px 渲染验收尚未完成，不应将此稿视为 UI 验收通过。

待执行验收清单：NPI 地图起步 → 导入 / 场景 / 资产说明与本地登记 → 下一步虚拟实验 → 实验记录；六页切换；选两车和工位；切三条路线；空表单报错、同起终报错、不同站入队；请求取消；三步断连对账并另建；地图预检开关；布局候选切换明确未载入；REAL 写入禁用；320 px / 1024 px 无横向溢出；Tab 与 Escape 可用。
